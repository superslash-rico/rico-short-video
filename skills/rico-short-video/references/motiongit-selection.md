# MotionGit模板选择策略

目标是让零基础到初级观众看懂实用AI方法、记住Rico，并能自然进入后续学习。选择依据是当前内容、真实素材和最终组合画面；网站Demo好看、下载量高或模板较新，只能提供候选线索。

本策略是本项目的制作方法，不是MotionGit官方评分。原先只规定画幅、人物、素材、许可和运行适配，首条纸面透视属于试跑，没有完成跨模板择优。纸面2.5.6只部分技术能力通过；当前绿色纸面或人物窗样式尚未获用户审美确认。

## 一、先写选择任务，再看模板

从已确定内容中提取六项，由助手据现有资料整理，不要求用户填表：

- 这条视频要解决什么问题，观众应带走哪一个可执行方法。
- 镜头分别需要表达观点、证据、步骤、比较、关系、成果或课程承接中的哪一种。
- 有哪些真实截图、录屏、文件与数据；长中文、竖长截图和必要来源标注占多少空间。
- 按source-modes.md判断原片类型；有人物时保护人脸、手势与可见范围，屏幕段保护当前操作、反馈和结果；读取实际构图与讲解速度。
- 已认可的系列视觉规范、输出画幅与平台片尾；没有认可规范时明确待定。
- 当前预算、已验证运行条件和交接形式。

前置写稿任务可在定稿后预选；现成原片任务从实际讲解/操作开始，按真实时码与目标区域终选。不能为了适配模板改掉用户的观点、事实限定或实际讲述。

## 二、发现候选，再筛必要条件

首次选型从当前正式目录及已有经验库了解可选范围。口播类优先，但需要特殊关系图解、成果展示或转场时可以扩展到其他类别。按[motiongit-library.md](motiongit-library.md)优先本地挑选，任务开始集中检查目录与相关发行变化，只补缺失或新增版本；不因重新选型而重复下载原包。

公开Demo、待认领作品和可领取模板分别标记；前两者可以研究视觉，不算已经可运行的生产方案。先在本地预览页按许可、用途、画幅与完整模板/动效片段筛选，再看候选动态；网页与随包许可冲突的条目暂不进入对外制作。模板名、分类和简介不能代替实际演示；未看动态就不能打动效质量分。每个候选核对实际版本，保留旧包，不因“最新版”直接覆盖在制工程。

初筛检查以下必要条件。明确不满足且没有可行解决方法的淘汰；未知项标为待验证，不能直接进入整条制作。

| 条件 | 具体判断 |
| --- | --- |
| 可取得且可合法使用 | 实际可获取，许可允许本条商业成片；第三方字体、音乐、图像单独核对 |
| 真实素材能替换并保持含义 | 必要截图/录屏能放入，目标文字和单位不被裁断；无用户案例时不能借作者示例冒充 |
| 当前模式的主展示受保护 | 露脸适用区间保持人物持续可见并按内容调度；纯拍屏保护操作目标、状态和反馈，不要求模板带人物；混合按实际可用区间核验 |
| 画幅和手机可读 | 整帧优先原生竖屏或实际重排通过；横屏也可作为局部卡片，但最终组合中的目标必须可读。密集整页缩成小字卡不能通过，应裁切、拆分或换组件，不能只裁成9:16 |
| 口播节奏与声音可保持 | 可适配真实时长、保留原速原声并有足够阅读时间；声音归属符合主工程规则 |
| 运行、交接与成本可接受 | 依赖可满足，输出可导入和核验，新增费用在授权内；透明通道未测不能假定可用 |

记录“模板本身不满足，但可由主工程解决”的条件及验证办法，避免既误用模板，也误删可用候选。适用露脸区间的纯动画遮掉人物不能通过；纯拍屏则以是否遮住必要操作/结果和资料可读性验收，不凭“没有人物”淘汰。背景均遵守相应同源视频加轻色罩的规则。

## 三、比较候选：质量优先的评分辅助

权重以[选取记录模板](../templates/motiongit-selection.json)中的criteria为准，总计100。每项按0—5打分：0为明确不满足，3为可用但需明显调整，5为对应本条内容表现很好；不了解填null，不能当0或5。每个分数附依据及证据层级，网页描述估计和真实小样评分分开。

| 维度 | 观察内容 |
| --- | --- |
| 内容表达 | 是否准确解释当前观点/关系，观众能否得到具体方法，课程承接是否清楚自然 |
| 真实资料与手机可读性 | 本期素材能否完整展示；长中文、数字、来源和虚构教学标签是否清楚；放大是否对应口播 |
| 人物与IP适配 | 按模式评分：露脸关注表情、口型与布局；拍屏关注Rico原声/署名、操作主展示和提示的适配；混合关注切换与同步。不以不存在的人脸表现填分 |
| 动效、声音与节奏 | 进入、强调、连接和退出是否服务讲述，有无读不完、无关运动或音效压人声 |
| 视觉一致与质感 | 字体、颜色、留白、线条、材质和运动语言能否与主工程及封面协调 |
| 稳定性与修改成本 | 实际导出/交接、替换长文案或素材、局部返工是否可靠，是否增加无益复杂度 |

总分只辅助比较：全部维度有评分时才按`sum(分数/5 × 权重)`计算；有未知项不重分配权重凑总分。内容错误、适用区间人物消失、必要操作/结果被遮或资料不可读，不能被炫目动效的高分抵消。同等质量下优先已验证、修改范围小的方案。不能用评分承诺播放量或会员转化。

## 四、主方向与镜头组件分两层选

一条视频优先保持一个主视觉方向，再按镜头任务选控件；需要其他模板的特殊动画时，先匹配共同字体、颜色、信息层级和运动节奏，核对连续画面，避免无理由拼接风格。

| 内容方向 | 可研究的候选方向，均需按本条验证 |
| --- | --- |
| 学习方法、观点、工作习惯 | 现代图文、纸面透视 |
| 软件实操、真实界面与操作证据 | 现代图文、科技控制台，按界面可读性选择 |
| 对比、步骤、机制和方法关系 | 纸面透视或其他有合适步骤/关系组件的正式模板 |
| 多项成果、作品展示 | 深色立体等展示方向，控制同时出现的信息量 |
| 轻快教程、互动提示 | 活力海报、鲜色角色等方向，与真人气质和内容严肃度匹配 |
| 开场或短视觉强调 | 适合的艺术/宣传类局部，必要时仍保留人物；不因题目有AI就默认科技特效 |

上表用于发现候选，不是逐类固定答案。组件同样按语义选择：步骤用顺序结构、对比用对照、证据用源图框选与局部、重点用文字层级。优先大字重点与逐项展开；模板需要整页小字才能填满版式时，调整组件或换选，不能原样套入。资料概览、局部裁切和手机检查按[presenter-layout.md](presenter-layout.md)执行。长句与多行资料优先矩形局部，圆形放大镜只用于能完整容纳的短目标。动态图表保留数据来源和单位，不为画面补造数字。控件数量不作为制作目标。

## 五、用相同的真实片段终选

尚无认可方案、内容类型明显变化或引入新模板/格式时，通常挑2—3个最有希望的候选；不批量试渲全部模板。用同一段实际口播、同一份资料、相同输出要求与必要人物区域比较，避免拿不同作者Demo直接排名。已有合适且获认可的同类方案时直接复用，按改动范围核验，无需每条重复风格投票。

样段通常选10—20秒能暴露问题的内容：有长中文/复杂资料、一次强调或切换，以及人物和声音。时长随信息需要调整。放到最终ChatCut布局中检查，不只看MotionGit单独预览；缩到手机观看尺寸确认关键内容不必放大才能看懂。

检查稳定画面与进入、移动、停留、退出阶段；核对整句文字、源图位置、脸与字幕安全区、动效与口播锚点、音效主次，再回读实际导出。不能把“成功渲染”写作内容准确，也不能把波形对齐写作完整试听。新整体风格用具体样段取得用户反馈；日常文字/位置修订沿用已有授权和风格。

没有候选满足关键要求时，调整布局/更换组件，或按双工具规范用ChatCut实现对应镜头；保留实际制作方与原因，不强行套模板。只有实际用到MotionGit的素材才标记为MotionGit成果。

## 六、留取舍与经验，下一条逐步变好

每条实际选型由助手把[选取记录模板](../templates/motiongit-selection.json)填入该条`剪辑工程/模板选取记录.json`。记录候选及版本、必要条件、分数依据、小样、最终选择与淘汰原因；主分镜和动画交接清单引用它，不复制维护多套结论。对用户只交代有影响的取舍和可看的样段，不把评分工作转给用户。

在随包[模板经验库](data/motiongit-experience.json)中按模板、版本、画幅及能力积累通用证据；本条私有素材和详细输出仍在本条目录。网页声明、动态演示已看、独立渲染通过、主工程组合通过、用户认可分别记录。配置错误或验收漏项不能直接判定整个模板不可用；新版要验证受影响能力，不自动继承旧版成败。

复盘记录本条何处好用、何处返工、是否复用及真实耗时。用户认可后才把风格和组件放入常用方案；保留新候选入口，兼顾系列一致性和内容适配。未来有真实完播、点击或会员转化数据时结合内容一起分析，不把一次播放变化归因于模板。

## 当前证据与本条内容的初选意见

2026年10月16日建库时核对正式目录两页，32款已下载并验签，现代图文、纸面透视、科技控制台竖版均已保存2.5.7；新包尚未在本机试渲。实际可用项和领取失败项见库索引，不将Demo或待认领作品数当可生产模板数。目录数字与版本不作为长期固定参数。

《AI工具更新这么快，普通人到底该怎么学？》适合先比较现代图文和纸面透视的竖屏方向：重点看观点、真实证据和“任务—初稿—核对—改进”关系。科技控制台是候选扩展，不是因为AI题材就默认采用。这里只是语义初选，未完成新模板的同段视觉对比，不能写成已择优。

已实跑的纸面透视竖版2.5.6证明部分图文渲染可用；原生人物解码失败，V1放大镜有配置/验收问题，整体未获用户通过。ChatCut约17秒样段的成功不是对MotionGit新版或跨工具交接的验证。
