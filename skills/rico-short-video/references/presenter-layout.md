# 人物随内容变化的画面编排

先按[source-modes.md](source-modes.md)判断素材类型和人物规则适用区间。本文件用于露脸口播及混合模式有可用露脸素材的镜头；纯拍屏按[screen-explainer.md](screen-explainer.md)，人物专用检查记为有原因的not_applicable。用户要求人物的位置和形态随内容变化。在适用区间，真实动态人物持续可见；位置、大小、裁切、窗形与资料的关系按每段表达选择。统一字体、边框和运动语言，保留构图变化的空间。

本文件是人物编排及肤色高光验收方法，配合[双工具流程](hybrid-workflow.md)使用。完整V2已验证部分全画幅、左右圆角窗、圆形窗及同源接续；2026年10月17日用户进一步固定了开头全屏真人和动态视频底图两项长期要求。抠像、自动跟踪及其他新形式仍按真实画面验证，不把制作规则当成已验收的样式。

## 固定的开场与背景规则

- **露脸口播先见本人。** 起始2—3秒保持全画幅清晰真人，默认前3秒；记录实际结束帧，之后再按内容缩窗。允许留白处的标题与字幕，脸部、表情和目光完整，不以前置纯动画替代真人开场。
- **缩窗时仍有真实环境。** 背景使用同一时点、铺满画布的真人视频，其上叠一层纯色半透明罩，再叠加清晰人物窗、资料和字幕。整帧纯色背景不得直接沿用为成片背景；MotionGit的不透明整帧模块应取成局部资料卡，露出这层动态底图。
- **背景有层次，前景有主次。** 调节罩色与透明度，背景人像只隐约出现一点轮廓与动态，实拍环境留下少量纹理即可；必要时适度虚化背景。前景人物窗和肤色保持清楚自然，避免两张同样抢眼的人脸。调整时以用户说的“人像更淡/更明显”为目标，区分画面可见度与色罩不透明度的相反方向。局部资料卡的必要底色以可读性为准。
- **同源、同钟、单原声。** 前景人物窗和背景视频不能分别从头播放，复用同一剪辑源与准确时点；只留一个主口播音轨。全画幅开场由清晰前景覆盖底图，不能因底层色罩给人物开场染色。

颜色、透明度、虚化强度属于每条的实现参数，不从本次试做冻结为长期标准。纯拍屏窗口或资料组合需背景时，采用相应同源屏幕视频加轻色罩，清晰主界面位于罩层上方；没有对应动态人物素材时不补造、冻结或循环人像。

## 肤色与高光专项检查

适用于清晰前景人像；同源装饰背景的明暗与色罩另行处理。动画、构图与肤色高光分别验收，整体效果认可不代替脸部局部检查。

1. **先确定色彩链路。** 探测原片的色域、传递函数、位深与范围，区分HLG/Dolby Vision HDR和SDR。保留原片；制作SDR工作源时执行实际色调映射，并回读工作源和最终编码的Rec.709及范围标签，避免重复转换。
2. **从最亮人脸段选样。** 原片开场、中段、转身或靠近光源后的最亮脸部、结尾均检查；光照明显变化时分段评估。先看全画面，再看100%额头、鼻梁、颧骨局部和手机观看尺寸，不能只用一个时点的缩略图选定全片参数。
3. **自然肤色和层次优先。** 检查脸部高光是否形成抢眼的大片发白、肤色和明暗过渡是否仍自然。局部亮度/直方图/示波器只辅助判断：尚未达到纯白或编码上限，也可能过亮、缺层次；白衣、屏幕或灯具的亮度不能替代皮肤区域验收。
4. **按素材控制高光。** 比较合适的高光映射与柔和过渡，必要时在当前工具验证局部高光控制，保留正常肤色中间调。不要只为压反光而把整张脸压暗，也不将某条的npl=300或500等参数设为下一条默认；新曲线或局部处理先做真实样段验证。
5. **导出后重新核对。** 依主时间轴与源入点找到同一人物时刻，对照原片的受控显示、工作源、最终MP4。分别记录高光在何阶段出现、导出有无进一步抬亮；导出画面还要检查100%面部和手机尺寸。抽帧技术通过、用户认可动画、没有硬剪切，均不能代替这项检查。

同帧定位、区域亮度对照及不同HDR映射的诊断静帧已有实测；没有通用于所有原片的局部调色预设。具体源时点、区域、指标和帧图由使用者保存在自己的任务目录。

## 先判断此刻观众主要看什么

| 当前表达任务 | 人物呈现候选 | 与内容配合 |
| --- | --- | --- |
| 开场提问、观点、亲身感受、关键判断 | 真人全画幅或较大的半身；必要时适度推近 | 让表情与目光承担表达，关键词放在实拍留白处。推近以原片清晰度和完整头部为限 |
| 解释少量要点、步骤或两种做法 | 人物与图解并列，或人物在下、资料在上 | 保留自然讲解和手势区域，图解逐项出现；竖屏按实际可读性选择上下或左右关系 |
| 展示软件操作、公告、原始记录、需要读清的证据 | 资料占主要区域，人物缩为清楚的圆角矩形窗 | 按当前源图目标、字幕和平台界面留白确定位置；关键资料变化时重新评估，不固定某个角 |
| 短提示、轻量过渡、资料占用空间较多 | 可试用圆形或紧凑的人物窗 | 适合看表情的短段；需要手势或较长讲解时选能容纳上半身的矩形形态，不把人物缩成标识 |
| 抽象关系、流程、前后比较 | 中等人物区域与图解/结果同屏 | 资料或关系为主要阅读目标，人物提供解释；必要时分步展开，维持一个清楚的视觉重点 |
| 总结、反问、行动建议、会员承接 | 人物恢复较大比例或全画幅，按需让出真实会员素材区域 | 将注意力带回Rico；出现会员页面时保留人物及资料必要阅读时间 |

可选抠像半身前景用于讲解者与图解交互，但需当前工具能力、头发/眼镜/衣服边缘及运动帧实际通过。未验证或边缘不稳时采用已验证的视频窗口。上述是内容候选，不要求每条用齐，也不设固定轮换顺序。

## 怎样选择位置、大小与形态

1. **先看原片。** 检查人脸、头顶、嘴、下巴、肩部、重要手势和真实朝向。原片只有半身就围绕现有素材编排，不补造未拍摄身体。需要保留手势时给矩形更大范围。存在文字或标志的实拍不为视线配合而随意镜像。
2. **给正在阅读的资料留位置。** 标出当前证据目标、标题、字幕带、平台交互区域和必要来源说明。比较可用位置；选能保留资料完整、脸部清楚且视觉关系自然的区域。圆角窗可在不同段位于不同位置，也可以改为上下/左右分区。
3. **用手机观看尺寸判断。** 不设全片固定面积配比。人物要能辨认表情和口型；资料的目标文字、数字和限定词也要能读。避免将密集整页等比缩成小卡，按下述资料规则裁切、分步展示或重排画面，不靠继续缩小人物或资料解决。
4. **分别选择窗形与运动。** 圆形强调头像，圆角矩形保留上半身，全幅保留实拍环境；窗形可随任务变化，不仅改变边角半径。形态变换是否连续插值由实际工具验证，不承诺所有遮罩能互相变形。
5. **保留一个清晰人物视觉中心。** 全画幅真人加资料时直接使用清晰真人层；缩窗时使用上述动态底图与半透明罩，前景人物窗承担讲述，背景人物只提供环境与动势，不能与前景同样清楚抢眼。

## 视频讲解资料的手机可读性

本节针对成片里需要观众阅读理解的资料。封面素材可用于表现本期内容丰富，不要求其小字逐字可读；按[封面规则](production.md)处理，不能据此删除用户希望保留的目录等素材。

- **一屏突出当前重点。** 先确定这句口播需要观众读懂什么，主卡用简短大字表达，避免在人物、标题和字幕之外再摆一整页密集小字。动画的信息丰富度来自准确的关系与逐步展开，不靠同屏塞满文字。
- **真实素材展示相关局部。** 裁切并放大正在讲的原文、数字或操作区域，保留完整含义、否定词、单位和必要状态限定；只给小字套高亮框仍算不可读。需要交代全貌时可先短暂概览，再进入可读局部，整页不承担细节讲解。
- **长内容分步讲。** 按口播逐项出现，必要时重排人物和资料位置。自行提炼的大字卡应与原始截图区分，不伪装成原文；来源和“教学示例·数据虚构”等必要标注保留。不能为简短把“未审核”“未完成”等含义删掉。
- **用最终组合验收。** 将实际成片按约360—390像素宽的手机观看尺寸预览，检查关键内容在正常播放和实际停留时间内能否读清，不依靠暂停、放大或桌面全屏。这个宽度是检查参考，不是统一字号或设备保证。读不清时改裁切、拆内容或重排，不继续缩小；停留覆盖实际阅读且避免人物、字幕与资料争抢注意力。

## 什么时候变化，什么时候稳定

从共鸣转入操作、资料出现/退出、讲述重点改变、进入总结或片尾时，重新安排人物与信息的主次。在一句重要判断上，可用适度推近强化；进入复杂阅读时，把人物放稳，让资料的高亮承担变化。

同一语义段、同一份资料的连续操作通常保持人物锚点，帮助观众找到稳定的讲述者。新资料确实遮挡当前人物区时，在资料切换处移位；不随每个光标动作来回换角，也不按固定秒数机械切换。变化应能说明“为什么此时要调整”。

从全画幅缩为人物窗，或人物移到另一侧，优先用同一动态视频层的连续缩放/位移，路径与中途尺寸也避开当前阅读目标。变换随真实句段和已确认的运动风格安排，停留覆盖完整阅读。跨句换镜可采用自然切换；不为形态变化强加复杂过渡。

窗口衔接保持同一原片的正确源时点和主时间轴。需要换视频实例或遮罩实现时，核对交接帧的人物姿态与口型，保持一份主原声；不使用冻结头像、示例人物、错位片段或先隐藏再出现来完成切换。

## 双工具交接与分镜记录

ChatCut主工程维护人物的实际布局、缩放、位置、裁切和字幕关系；MotionGit负责的动画按本镜头可用空间编排。先定人物和资料的组合，再给动画留区域；人物有移动时传递整个移动过程的保护区域，不能只传终点位置。空间不足时重排动画或人物，不让不透明模块盖掉真人。

在[交接清单](../templates/animation-handoff.json)每个镜头的`presenter_layout`中记录：

- 语义任务、呈现方式、形态与选择原因。
- 人物起止矩形、必要的中间关键帧和源裁切依据；位置相对最终画布归一化，时码使用主工程帧数。
- 变化的口播锚点、过渡区间、稳定停留区间，以及与资料/字幕保护区的关系。
- 真人开场结束帧，以及背景视频源、同源时钟、罩色/透明度、声音归属和前景未被染色的检查。
- 新圆形遮罩、抠像或其他新形式的实际能力证据；未验证项保持待验证。

这些是制作记录，不是ChatCut或MotionGit的API字段。执行时读取工具当时的实际合同。既有v1/v2/v3清单保留可读，不强制迁移旧片段；新镜头按v4记录模式与适用范围，露脸镜头记录开场/背景，屏幕镜头记录操作事件与源时点映射。

审核实际组合画面的开头0—3秒、缩窗进入、运动中段、稳定阅读、退出及相邻切点，确认真人全程可见、头部/重要手势完整、动态背景仍能辨认、前景肤色未被罩色污染、资料可读、路径不遮关键内容及口型时点一致。最后核对编码成片，抽帧与“有运动”不等于连续观看、试听或用户审美认可。

## 本条视频的编排例子

《AI工具更新这么快，普通人到底该怎么学？》可从“本人提问与共鸣 → 工具资料出现并让出空间 → 本人较大画面提出真实任务 → 周报示例与人物并列 → 核对资料为主、人物稳住 → 本人回到主要位置总结方法 → 本人与真实会员素材共同收尾”展开。具体位置依据本条真实原片和资料落位，不把这个顺序套用到其他主题。
