# 从确定主题到发布包

## 1. 建档与状态

确定主题后，在当前项目下建立 YYYY-MM-DD-主题 子目录，使用 Asia/Shanghai 当天日期；已有目录先读内容，必要时加序号区分，不覆盖。主题中的路径分隔符和不安全字符作正常文件名处理。

先按[source-modes.md](source-modes.md)查看素材并记录input_mode、判断依据、entry_path、主原声与各素材角色/可用区间。原片已拍好时可据已有内容命名主题并直接接续；目录只创建实际需要的文件，不制造不存在的前置定稿。

保存用户原话、必讲点、补充思路与来源到主题说明.md；外部 bot 的内容作为输入资料，事实与能力声明仍须核验。来源软件不是执行依赖。

目录按实际阶段填充，不创建假成果文件：

~~~text
YYYY-MM-DD-主题/
├─ 主题说明.md
├─ 制作状态.json
├─ 口播逐字稿.md
├─ 素材/
│  └─ 素材清单.md
├─ 口播原片/
├─ 剪辑工程/
│  ├─ 剪辑决策与时间轴.json
│  └─ 分镜与音效.md
├─ 成片/
├─ 封面/
├─ 四平台发布文案.md
├─ 审核与发布记录.md
└─ 复盘.md
~~~

制作状态.json 至少记录任务 ID、主题、当前阶段、技能版本、输入与产出路径、已确认稿件的版本或摘要、原片清单、当前发布包版本、各平台状态、等待内容与下一步。没有实际确认时保留空值。确认记录指向用户消息及当时文件，不能由脚本或网页自造。

状态随阶段变化：写稿、待用户定稿、素材准备、待原片、剪辑包装、待成片审核、发布中、制作已交付、发布已结束、用户确认完成后已归档。制作、发布与归档分别记录；归档不覆盖未发布事实。

## 2. 按入口准备稿件或分析现成原片

以下逐字稿规则用于选择前置写稿的任务。未拍的拍屏讲解可先给三到五点演示提纲；已提供原片并要求制作时直接转写、理解和剪辑，不必倒补逐字稿。其实际转写/剪辑提纲作为制作依据，不记录虚构的用户定稿确认。拍屏及混合的屏幕段继续读[screen-explainer.md](screen-explainer.md)。

- 按[writing.md](writing.md)优先使用可发现的rico-spoken-script；缺失时用随包风格与字数工具，不要求其它项目或原始课程硬盘存在。通用风格仍由原写稿技能维护，随包内容是明确来源的备用快照。
- 围绕一个具体问题、一个核心判断或一个可见结果组织两分钟内容，忠实覆盖用户的必讲点。事实、个人经历、课程能力与演示结果均有依据。
- 初稿可按约 500—600 汉字规划，英语、数字与演示静默另看；运行写稿技能的时长工具，实际时长以试读和成片为准。
- 口播逐字稿.md 仅含可朗读正文；来源、时长估算、分镜和说明放在其他文件或回复中。
- 如视频号与其他平台需要不同的口播片尾，分别提供纯正文稿，例如口播逐字稿-关注版.md，并在录制前说明需要补录的片尾。不要把两个结尾连写进同一份提词正文。
- 用户修改后保留先前版本，明确当前定稿。未定稿前可核对写稿事实，不提前开展整套正式素材与动画制作。

课程参考在随包[课程目录快照](data/course-catalog.json)；当前项目或用户提供更新内容时以新事实为准。该快照带日期，不能视为所有课节均已上线的证明。

## 3. 真实素材与录制交接

前置写稿的任务在逐字稿定稿后；已有原片的任务在理解实际声音、画面及用户重点后，建立“语句 → 画面/操作事件 → 素材 → 动画 → 音效”关系。先看用户已经提供并命名的素材，再补充官方页面、真实界面截图、录屏、公告、图表或实测成果，丰富度服务内容。

素材清单为每项记录稳定 ID、文件路径、内容说明、来源 URL 或用户提供、采集日期、原始事件日期、素材性质、许可或可用条件、拟使用语句与必要裁切。用户文件名帮助理解，仍检查内容是否对应。

此时可按motiongit-selection.md预选视觉方向和模板，但录制前的时长、人物区与动效评分仍是计划。收到原片并完成粗剪后，再用实际素材与声音完成终选，不把稿件预选当成模板已经适配成片。

- 截图保留可追溯来源；裁切不得改变事实含义。展示品牌、图片和音乐等按实际使用条件处理。
- 官方演示、自己的实测、用户案例和辅助图解分清。未复现的结果不能写成“我已经做到了”。
- 生成图片适合封面或图解，不能替代所声称的真实资料。生成或编辑位图时使用当前可用的 imagegen 技能与工具。
- 时效性消息在定稿与发布前复核。重要事实变动时同步修改稿件、画面及平台文案。
- 只向用户交代本条视频必要的录制提示，例如画幅、构图、需要补录的结尾。用户把原片放入主题目录后，再整理到口播原片，保留原文件可恢复。

## 4. 原片粗剪

先读媒体信息、时长、帧率、分辨率与音轨；保留原片。默认在ChatCut完成可编辑的口播主线与转写，按当前官方口播技能执行，再结合实际声音识别口误、重复、无效停顿和语气词。FFmpeg及少量脚本用于必要的方向/HDR/格式处理、已有模板渲染的片段整理和质量检查；通常无需再写一套整片剪辑合成器。

拍屏及混合的屏幕段须先标出需要保留的视觉事件与顺序，再安排停顿清理、变速与剪辑；不直接按转写静音删掉操作反馈、等待和结果。双源先核对真实同步锚点，保留源到主时间轴的映射。

静音检测、VAD 或 ASR 用于提出切点；结合上下文试听或检查，保留词头词尾、必要停顿、重音、转折和否定。不能仅用固定毫秒阈值或某个词名单整批删掉。检查跨句跳切、音画同步与呼吸突变。

剪辑决策与时间轴记录原片起止、保留或删除原因、成片对应位置、字幕与素材的时间基准。修订粗剪后更新后续动画和字幕，避免沿用旧时间轴。字幕以实际成片声音为准，用定稿校对术语，不让字幕虚构用户没有说出的结论。

不能确认的错读或必讲内容缺失，提供具体补录范围；继续完成不依赖补录的工作。

## 5. 动画、音效与成片

先按hybrid-workflow.md分配分镜：ChatCut维护主时间轴、真人、字幕、声音和最终输出；MotionGit按实际模板合同制作值得强化的动画。各工具细节读chatcut.md与motiongit.md。先固定可制作的口播版本、当前素材与画面区域，再制作必要样段和动画，最后回主工程总装。每个镜头明确一个动画负责方。

在已验证的粗剪时间轴上，按[presenter-layout.md](presenter-layout.md)逐镜头选择人物呈现：观点与情绪、操作与证据、方法图解和课程承接可采用不同的位置、大小、裁切及形态。先记录变化原因、人物起止位置、过渡与资料保护区；同一语义段保持必要稳定。在source-modes.md判定为适用人物持续可见的区间，人物层覆盖相应口播且保持可见；大面积资料画面保留清晰的动态人物区域。按真实画面安排平滑缩放与移动，不能只在部分镜头合入人物，或让不透明动画再次盖住人物。

跨工具首次交接要验证实际文件的时长、帧率、画幅、声音和透明情况。无alpha的动画使用局部资料卡与人物窗组合；只有经过导入和最终输出验证的alpha素材才作为透明覆盖层。默认仅保留ChatCut的一套总字幕和一份主口播，避免将MotionGit混合旁白重复叠入。

公开署名只用“Rico”。导出前检查名牌、片头片尾、封面、发布文案和作者信息，不能从私有身份或历史脚本自动补入其他姓名。

纯拍屏以真实操作为主展示；混合模式按实际素材覆盖切换人物和屏幕段，不冻结/循环短片头。屏幕窗口需背景时用相应同源屏幕视频加轻色罩，前景目标保持清楚。

放大效果先在原始素材中记录目标文字/控件及源像素矩形，再映射到实际显示区域；计入contain留边、裁切、缩放和父层变换。放大区与原图使用同一素材、同一变换关系；长内容采用局部裁切卡加框选/连线。逐处检查入场、移动、停留和退出，确认目标完整、可读、与当前口播对应，且不遮人物或字幕。动画有运动、媒体文件正确或某几个时点有内容，不足以验收取景正确。

每个核心论点都应有可理解的画面支持：关键文字、真实界面局部、步骤、关系或对比。动画密度高，同时留出阅读和理解时间；避免遮脸、遮字幕、把所有元素同时堆满，或只换背景而没有有效信息。

动作音效与进入、强调、转场等有明确对应，保存来源与时间点。旁白始终清楚，音乐与音效不过载、不压人声；无法获得合适音效时说明实际缺口，不把无音效版本称为包装完成。

导出前检查全片画面、声音、字幕和事实；额外抽查切点、动画最密处、长字幕、首尾与各平台片尾。检查实际输出时长、画幅、黑帧、裁切、缺失素材、字幕同步、音量和可播放性。无法实际播放或实听的部分明确记录为未验证。

交付 MP4、可编辑工程、字幕或时间轴，以及可在本机继续渲染的说明。两分钟是目标，实际超长时压缩旁枝与重复或提出取舍，不暗删用户必讲内容。

## 6. 封面与平台文案

封面根据主题、成片观点和真实素材制作，标题清楚、文字醒目、画面相关。先读取用户指定的上一条最终封面及索引，跨露脸、拍屏与混合模式沿用同一系列的字体气质、色彩、层级和作者标识；首次尚无基准时制作可审核方案，不自行将新画风当作用户已认可。具体样式来源和安全区保存在任务封面索引。

默认交付16:9、3:4、4:3三种比例，各自重排标题、人物与真实素材，不以一张裁切代替独立设计。可按1600×900、1080×1440、1440×1080导出PNG及JPG；平台有新要求时以实际为准。保留每种比例的原生生成图、完整提示词和引用素材入口，尺寸标准化只用于技术导出。逐张核对标题、人像辨识度、产品形态、无遮挡、手机尺寸主次和实际像素尺寸，用户认可另行记录。

封面中工具目录、课程资料和界面截图可作为内容丰富的视觉线索，素材内的小字无需逐字可读；不要把视频讲解卡的阅读标准套用到封面并自动删素材。保持主标题、人物和相关素材的主次，来源可追溯，不编造产品背书、实测结果或教学成果。生成合成不能冒充未改动的原始截图。

纯拍屏封面可用真实界面、结果与醒目主题呈现；有适用肖像及当前使用者的用途许可时，也可加入本人。记录实际来源与许可，不继承维护者的肖像授权；视频不露脸不等于封面禁用人物，也不推导每张封面必须有人。不从其他私人档案擅取无关人像。

人像可按用户要求去除临时痘印、均匀肤色并自然提亮牙齿，保持本人身份与表情可信。新风格先保留对照与可审核版本；“野兽先生”式视觉张力可通过鲜明对比、轮廓分离和人物精神状态表达，具体程度待用户确认。仅修改封面时，不连带重剪或美化视频人物。

四平台发布文案.md 分别给出标题、正文、标签、片尾与文件对应。视频号使用已确认会员权益，其他平台以关注和继续学习承接。核对平台当前字段、长度、画幅与封面入口，不能假定四站完全一致。

最终审核包清楚列出本次成片、封面、文案与版本，用户可直接打开查看。按 publishing.md 准备表单并停在最终按钮前；最终提交由用户自己点击，或经用户明确授权助手点击后再执行。内容确认与最终点击授权分别记录。

制作交付完成时执行 evolution.md。若后续才发布或用户修改，接续同一条复盘，不把等待用户当成整个制作链路已完成。

## 7. 用户确认完成后的归档

用户明确结束本条任务后，执行[archiving.md](archiving.md)：吸收有价值的方法与长期要求，核对当前成果和依赖，保留最终文件与精简复剪备份，再按清单删除缓存、淘汰版本和无用过程文件。将阶段性复盘与审核说明汇成`归档记录/完成总结.md`，用`00-归档说明.md`导航成果；当前状态只指向真实保留路径。制作期间保留的旧稿、旧动画与源截图，在结案时按实际复剪依赖取舍，不永久无上限累积。
