# 发布交接：先检测蚁小二，再调用独立技能

Rico于2026-11-16明确要求今后短视频发布使用独立的蚁小二 `yixiaoer` 技能。本技能负责制作、备齐发布材料、传递已有授权及回收结果；安装与发布能力由蚁小二技能自身维护，两个技能保持独立。

## 1. 发布环节首先检测技能

1. 检查当前宿主的可用技能列表及其实际技能目录，确认能读取正式 `yixiaoer` 的 `SKILL.md`。不要只凭 `yxer` 命令存在或有 `yixiaoer-cli` 安装助手，就认定正式发布技能已安装。
2. **已有正式技能：直接读取并调用。** 向它提供下方发布包，按它的当前规则继续；不因进入新短视频任务就重复安装或强制升级。
3. **没有正式技能：先安装再继续。** 若 `yxer` 已可用，使用其官方 `yxer skill sync --global` 将正式技能同步到当前宿主可发现的目录；CLI也缺失时，按 [SkillHub安装说明](https://skillhub.cn/install/skillhub.md)将 `yixiaoer-cli` 安装助手装到当前Agent的skills目录，读取助手并完成CLI安装及正式技能同步。安装后重新检查正式技能入口和CLI，再调用它继续发布。不能默认装到无人读取的项目 `./skills/`，也不顺便改变全局技能源优先级。
4. 沿用本机已有的有效认证和配置；只在确实缺少或失效时请用户补齐。API Key、Client ID、账号授权均留在使用者本机配置中，不写入本技能、公开资源或发布素材包。安装受阻时说明具体缺口并保留发布包，不假称已可调用，也不自行改回逐站浏览器发布。

技能可读取后，由蚁小二检查CLI与认证环境；其视频上传需要可用的FFmpeg，自动读取媒体信息时还需要ffprobe。缺少依赖时按它的当前说明处理具体缺口，不将技能文件存在等同于发布环境已就绪。

## 2. 剪辑交付时备齐发布包

在本条视频目录保存 `发布准备/发布交接.md`，由助手填写并更新；现有文案、封面和成片用实际绝对路径引用，不另造一套互相冲突的副本。未确认项如实标为待补，不能把候选当作已确认数据。

| 材料 | 交接清单必须说明 |
| --- | --- |
| 最终视频 | 每个目标平台对应的MP4绝对路径、版本、SHA256、文件大小、时长、宽高、帧率及实际音视频编码；已审主片可共用，有平台片尾差异时逐个平台映射。保持文件稳定可读，不传预览、测试片或淘汰版。 |
| 独立封面图片 | 每个平台实际选用的PNG/JPG绝对路径、版本、宽高、比例与文件大小，主封面及确需的横/竖版分别标明。沿用production.md的16:9、3:4、4:3独立构图；按当前平台需要选择或补充。封面不能只有视频内的一帧、预览链接或编辑工程，缺失时在制作环节补齐。 |
| 分平台文案 | 引用 `四平台发布文案.md`，分别准备标题、正文/简介、话题与标签清单、需要时的短标题；话题意向与正文分开保存，由蚁小二按当前平台字段装配，不预写猜测的HTML或动态对象。视频号使用已确认会员承接，其他平台以关注与继续学习承接。 |
| 发布目标 | 沿用当前任务或本机profile中已确认的平台与本人账号，记录账号名称/明确ID、来源和确认范围。常用四平台是抖音、视频号、小红书、B站；只交接本次已确认范围，不因蚁小二支持更多平台而扩大。蚁小二发布时核对真实账号及状态；名称不唯一或身份不明才补问。 |
| 发布设置 | 记录可见范围、立即发布/定时/仅草稿、明确的发布通道及其依据；定时写清日期、时间和Asia/Shanghai时区。未指定通道时交由蚁小二按当前默认规则处理，不因本机有Client ID就擅自改成本机发布。沿用本机认证配置，不把密钥或实际Client ID复制进交接文件。 |
| 审核与声明依据 | 引用 `审核与发布记录.md` 中用户对本次最终视频的明确通过消息、对应版本与SHA，以及已确认的平台/账号/设置授权。记录自制或转载及来源、AI素材/数字人/配音等实际使用情况和已有声明要求，供蚁小二正确映射；不杜撰原创、权限或AI声明。 |
| 可选挂载意向 | 如本次需要分区、合集、平台音乐、位置、活动、商品或其他挂载，记录已有选择和来源；例如B站分区意向及独立标签清单。真实动态ID与完整对象由蚁小二在发布时查询，不提前编造。 |

交接前核对文件存在且能读取、视频SHA与本人已审版本一致、封面及文案映射无误、必需项没有示例值。视频号等平台的封面用途参数和压缩，由蚁小二按其当前规则处理；这里准备独立封面及真实尺寸/大小，保留高质量母版。上传资源只引用蚁小二真实回执，不能把本地路径或外部URL冒充已上传的资源Key。

本清单是剪辑成果与发布意图，不是蚁小二的 `payload.json`。账号、分区、话题、上传Key和来源回执由发布技能按当前契约获取并校验有效性，不从旧片复制后假称仍有效。字段、枚举、字数和图片限制随平台变化，以发布时蚁小二的实际契约为准；随包 `data/platform-fields.json` 仅是带日期的历史浏览器观察，不是CLI的现行规格。

核对依据：2026-11-16安装的 `yixiaoer` 3.2.33，其视频发布、标准发布、资源上传和四平台文档。这里只维护制作端需要准备的输入，不复制这些文档、接口schema或CLI发布实现；升级后按独立技能当前要求补齐必要材料。

## 3. 沿用成片批准，交给蚁小二继续执行

Rico于2026-11-02明确授权：本人审核本次最终成片通过后，助手直接完成已确认平台、本人账号和设置范围内的上传、填写、必要草稿暂存、最终发布与结果核验。文案、封面与字段由助手核对，不默认停草稿或另请批准最终按钮。仅适用于Rico本人；其他使用者不继承其个人授权。当前要求“先看文案/只存草稿/暂不发布/定时”等优先。

把发布交接清单、对应成片批准及目标范围一起交给独立 `yixiaoer` 技能；读取它自己的 `SKILL.md`，再按它指向的共享规则、发布域、标准发布与视频工作流操作。由它完成真实账号选择、视频与封面分别上传、字段/来源校验、预览、提交及状态查询；不要在剪辑技能内另写CLI参数、payload模板或浏览器发布流程。已有明确授权持续有效，不因切换技能而重复询问，但修改本技能本身不等于任意视频已通过或已获发布授权。

没有本次完整成片批准时，可备齐材料和安装依赖，发布保持待审核。成片实质修改后不把旧批准挂到新版本；普通元数据适配不新增无关审核。必须本人重新授权账号、扫码或客户端登录时，只交接具体缺口，继续其他可独立完成的平台。确需浏览器登录时，仍先退出自动控制、保留页面，等用户明确完成后再恢复，不在用户登录期间轮询或操作登录页。

## 4. 结果回写与恢复

接回蚁小二的逐平台实际结果，更新 `制作状态.json`、`审核与发布记录.md` 和本条复盘：记录所用发布包版本、平台/账号、提交时间、任务标识、作品ID/链接、实际状态及具体缺口。未开始、待安装/配置、待登录、已上传、草稿、已受理/审核中、已发布与失败分别记录；任务ID或受理成功不等于平台已公开发布。

超时、网络断开或状态不明时，让蚁小二先查询原任务/发布记录，确认状态后恢复，不为取得成功回执盲目重发。简短回报各平台真实状态和可用作品链接；部分平台完成不写成全部完成。没有另行要求，不建立周期监控或自动任务，发布成功也不推导删除原件权限；用户明确结束任务后再按archiving.md归档。
