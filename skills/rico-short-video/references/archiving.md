# 用户确认完成后的收尾与归档

## 触发和范围

用户明确说“本条任务完成”“这条可以结案”等后执行。当前用户已授权以后在此节点整理该视频目录，无需为同一范围再问一次。审核版交付、等待修改、草稿保存、自动化完成提示不代替用户确认。若用户只宣布剪辑制作完成，按制作范围归档，平台未发布仍如实保留未发布状态。

默认只清理当前视频任务目录。共享私有模板库、技能迭代快照、其他任务、浏览器缓存/登录态/本地草稿、云端ChatCut工程及平台作品不在范围内。文件正在使用时不移动或覆盖它；关闭应用、卸载软件与云端删除需要独立任务范围。

## 顺序：总结 → 锁定 → 备份 → 验证 → 清理

1. 读当前状态、实际存在的用户定稿或原片转写/剪辑提纲、反馈和发布回执，锁定最终成片、封面、文案、各源原片与主时间轴。现成原片入口不补造前置定稿确认。先盘点路径、类型、大小、链接及占用，不能把名为cache或旧版的目录直接整删。
2. 按evolution.md把长期要求和可复用经验合并到最相关细则，替换旧结论；单条事实保留在归档总结。修订前快照、修订后校验。技能只存方法、无私人资产的参数规范和入口，不装入本条人像、原片或账户包。
3. 形成明确保留清单并核对工程依赖。最终可编辑工程不仅是网址：备份实际活动时间轴、各项实例属性/覆盖参数、资产映射、原生字幕、动画源码、使用媒体、MotionGit源参数和来源/许可。口播剪辑决策与源区间映射用于复剪时应保留；拍屏/混合还保留必要操作锚点、等待变速、双源同步和补录状态依据，手机与电脑录屏的唯一原件分别保留；不是只留MP4就宣称可编辑。
4. 检查当前导出限制。首条ChatCut的FCP XML实测遗漏motion-graphic及captions，只能作兼容参考；另存本机/云端工程状态、MG代码及字幕。导出成功不代表可完整还原。临时编辑器登录链接、signed URL、Key、Cookie和带凭据的原始工具响应不入包；只保存干净工程网址与已净化的数据。
5. 工程恢复所需媒体只留一份，按准确文件名/哈希列资产映射。保留唯一原片；去掉重复代理、静音人像副本和旧渲染前，确认后续工程不再引用它们。MotionGit个人模板包仍在共享私有库，归档只记录模板ID/版本与引用，不复制含账户Key的包。
6. 打包可编辑源与必要证据，校验ZIP CRC、成员清单和哈希；抽查实际图像/字幕/参数可读，明确缺失或仅云端可用的依赖及恢复方式。未取得完整依赖时不能自称完全离线可还原；不能为填补缺口绕过认证。唯一或身份不明的文件先保留，清理已确认无用项，不让小缺口阻断整条归档。
7. 使用具体文件清单清理。删除重建型模型/venv、临时音频、失败渲染、过期样段与成片、重复素材、测试截帧和已归纳日志。不要把这些整包搬进项目资料伪装减量，也不删除符号链接的目标。保留一份精简审计即可，不保留整段含令牌日志。
8. 回读最终目录、播放/探测最终成果，比较关键文件清理前后SHA；回读工程包和全部保留项。记录删除数量/字节、清理前后目录大小、保留成果、仍在云端的工程、发布状态及恢复限制。只有实际执行后报告已清理。

## 默认最终目录

~~~text
日期-主题/
  00-归档说明.md           # 成果导航、完成范围、继续修改入口
  制作状态.json            # 当前结案状态，不堆叠死链接
  口播逐字稿.md
  四平台发布文案.md
  成片/                    # 每个真正不同的平台版本各一份，不留失败审核副本
  封面/                    # 最终各比例PNG/JPG、最终索引
  口播原片/                # 唯一原件，保留原路径优先
  工程/                    # 精简复剪包、动画源、封面再编辑参考与恢复说明
  归档记录/                # 一份总结、必要的来源/许可/验收与发布证据、保留清单
~~~

目录以已有依赖为先，不为统一外观破坏仍在用的路径。封面生成PNG/提示词是再编辑参考，不冒充可分层PSD。私人原片与工程包属于本地私有归档，对外仅分享已批准成果。此前已经被删除的输入不补造。

详细删除计划和前后统计可存`项目资料/任务归档记录/本条ID/日期/`，保留路径、摘要、理由与简短状态，避免再次制造大量过程文件。目录内保留一份人能看懂的结果；清理记录和保留清单本身不必互相循环记录哈希。

## 可复用清理工具

`scripts/closeout.py inventory --root <本条目录> --output <目录外盘点.json>`读取文件，叶子符号链接不跟随。

先由助手人工判断保留项并写JSON数组（相对路径）；再执行：

~~~text
python3 scripts/closeout.py plan --root <本条目录> --keep <保留路径数组.json> --output <目录外删除计划.json>
python3 scripts/closeout.py clean --root <同一本条目录> --plan <删除计划.json> --result <目录外执行结果.json> --confirmed-complete
~~~

`--confirmed-complete`表示已在会话中核实人类完成确认，不是工具自动生成授权。plan会固定全部文件身份和保留文件哈希；clean先核验目录文件集、每个文件及ZIP CRC，任一变化都在开始删除前拒绝。之后逐项复核、只删清单文件和空目录。输出与计划放在任务目录外，不把计划覆盖、范围猜测或脚本通过当作内容取舍。

测试范围应覆盖：正常清理、文件变化时不动任何文件、越界/符号链接祖先拒绝、保护重叠拒绝、删除叶子链接时目标完整。清理仍需助手盘点依赖和检验成果，脚本不识别“哪个视频是最终版”。
