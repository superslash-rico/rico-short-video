# 横竖屏共用的MG视觉、工艺与质量规范

2026-10-22用户已确认：竖屏短视频与长视频共用一套MG风格和质量标准，分别适配构图与取景；短视频既有人像窗口、主剪、字幕、声音、色彩、封面和发布流程保留。本页是短视频端的统一入口，[共享包清单](../assets/mg-shared/standard.json)保存版本、参数、组件和参考索引。单条视频的临时配色、裁切补丁不能反向成为默认规范。

## 1. 同源视觉与工艺

- 专业动画主展示采用`#0C0A14`深紫黑底、正常观看清楚可见但不抢主体的简约点阵、画面中部横向柔和淡紫微光。背景辅助空间感，不加建筑、舞台、光廊等复杂装饰。真实界面与普通人物原片上的局部透明叠加不强制改底。
- MG使用原版MiSans并核对实际渲染；标题、正文、批注、辅助信息有一致字级与读序。新绘解释层采用共同的紫色强调、浅色纸面和深色正文；真实原件保留自身颜色。强调色与材质从共享包取得，避免每条视频另拼一套图标卡片视觉。
- 需要表达记录、页面、材料等对象时，沿用长片参考的纸面层次、薄边/厚度、高光、接触影与悬浮影、统一光向和透视。按语义做拆解、提取、修改、交接与归位，使同一对象从前态变成后态。图标和卡片可以服务内容，但不能替代整个解释机制。
- 摄影机负责观察，对象负责变化。统一整体—细节的明显反差、利落过渡、抵达后的读时和必要轻推；具体取景、秒数与倍率由完整阅读单位、口播与画幅计算。旧样例的约4倍反差、18帧或3.5%只是其实现，不能成为每镜固定配方。
- 点阵读取前景实际相机状态，作较弱的缩放和位移；微光响应更弱，作为二维远景视差。背景不得自行运行另一条强烈推拉轨迹。固定层级为底色/微光/点阵 → 场景对象 → 人物 → 主字幕；点阵不得盖在纸面、文字、图标或真人上。非焦点纸面仍保持不透明，用物体内部的明暗/色调变化弱化；不得通过降低整张纸或父级透明度让底层点阵透出来。默认关闭常驻Rico角标。

## 2. 全画幅场景，保护区不作裁切框

专业解释场景的MG资产、根容器与时间轴实例使用当前工程完整画幅，竖屏默认1080×1920，横屏按实际16:9画布；实例落在画布原点，宽高对应完整输出。世界空间可以大于画布，子对象可以延伸到画面之外，相机决定最终可见部分。

场景根、相机世界层不增加中间`overflow:hidden`、固定高度窗口、顶部/底部挡带或父级蒙版；实际输出画布边缘才是最终取景边界。仅把CSS改为visible仍不够：必须核对资产自然尺寸、实例矩形、父级clip/mask/crop和烘焙素材边界，避免资产仍以局部画布栅格化。

人物、字幕、关键界面和平台区域是动态排版/避让约束，不是动画的硬裁切边界。通过整体构图、运动路线、层级、时间错开和重新取景保护内容；主要阅读单位不能被人像遮住，也不把人物缩成标识。已有视频要求保留人物窗时沿用其原坐标、源映射、形态和时序，不借本规范改动它。

照片/原件的局部裁切、纸张内部的真实内容窗口、物体自身圆角等有明确用途的蒙版可以保留，记录它属于哪个对象。主动安排非焦点内容出画与中间窗口意外截字分开验收。专业背景不含同源实拍时，背景视频/色罩专用检查记有原因的not_applicable；人物源时钟、口型连续和前景/远景相机联动仍须分别核验。

真正简短的关键词或局部透明提示仍可用内容尺寸资产；其边界应容纳完整运动、阴影与极值。需要整体—细节运镜的专业场景不能继续套此类小资产，或仅通过等比缩放横屏作品变成竖屏。

## 3. 共用组件，横竖屏分别构图

共享包的[场景骨架](../assets/mg-shared/SceneRoot.jsx)、[几何与取景](../assets/mg-shared/geometry.js)、[纸面组件](../assets/mg-shared/PaperSurface.jsx)作为共同实现起点。复制所用组件及参数/许可到本条工程，保存包版本和文件摘要；不在每个视频里另造默认裁切窗口或另一套材质。这些是支持模块，不直接作为成片资产导入；本条另写唯一导出入口，读取item.props及实际frame/fps，再组合组件并注册对应属性。组件不是完整动画模板，内容与编舞仍按本片设计。

这套骨架区分最终画布、世界坐标、实际相机和可读区域。可读区域用于计算取景，**不生成clip或蒙版**。同一个取景结果同时驱动前景和远景视差。需要更复杂2.5D/3D时，扩展同一坐标与投影机制并原生验证，不把平面缩放宣称为真实推轨。

16:9与9:16各自重排分组、整体轮廓、阅读方向、相机目标及人物避让，保持对象身份、材质、字级关系和同一理解机制。按最终屏幕中的投影尺寸与完整阅读单位确定特写；竖屏按约360—390像素宽审核。保留原有短视频人物显示逻辑，不移植长片固定圆窗或字幕制作方式。

本轮把可供共用的规范与骨架随短视频技能维护；没有自动修改长视频技能或建立另一份全局技能。长视频端后续接入应引用同一包ID/版本与组件源，不另抄一份独立规范。未接入前不能声称两套代码已经同步。

## 4. 有实际参考，明确认可范围

按[参考索引](data/mg-reference-index.json)取得并观看真实定格、时序和动态，再研究对应源；不能只看名称、颜色或一张封面。运行`scripts/mg_references.py`列资源，提供`--source-dir`可从已下载的长视频技能核验并复制到技能外缓存；需要下载时显式用`--download`，读取实际输出路径。字体与许可按相同来源核验，参考人像/声音不作为新片媒体。

长片“项目记录”仅有材质、透视、拆解归位与身份连续的局部工艺研究价值；其旧整体构图、内容与相机路径不能直接改字投产。长技能明确尚无最新整体标准完整获批样片。被否定的FDE等旧探索不列为成功参考。

短视频10月22日的V2/V3已被用户指出风格、质量与固定窗口问题，属于反例，不是当前样片或新组件的验收证据。随后V4同语义横竖样段的纸面、空间层次和镜头推拉已获用户认可；点阵层级、去角标与字幕设计修正已用于整片。后续V5加入真实软件图标，V6换成积极配乐，用户已确认发布并完成。可移植验证范围见[原生MG案例](data/first-native-mg-case.json)，不能继续把这套方法记为“尚待首次实跑”。

已有认可基准时直接沿用其视觉、工艺与镜头量感；不为每条常规内容重新征求风格许可。Rico项目优先从本机profile定位已认可横竖样段；私人影片不随公开技能分发。随包[纯MG研究场景](../assets/mg-shared/TaskCapabilityStudy.jsx)和[属性](../assets/mg-shared/study-properties.json)保留该基准的同对象、双画幅布局、纸面明暗与运镜代码，不包含人像、声音或真实截图，也不代替本条组合检查。新机制或实质改变风格时，再用同一语义单元制作横、竖对照样段：包含独立成立的整体、一个精修对象、可见变化、特写、返回整体，以及实际人物/字幕组合。约10—15秒可作选段参考，以完整理解为准；本条可用“自己做好与带队达标”。先交可审核样段确认共同风格与质量，再按其扩大生产。已有同版本、同机制的认可基准可复用，常规改文案不重复选风格或增加逐镜头审批。

## 5. 同一套质量检查

| 检查 | 实际证据与通过条件 |
| --- | --- |
| 整体 | 开场/重组/结果构图的分组、重心、留白与视觉中心成立；不靠无限拉远凑总览 |
| 对象 | 完整内容、前态/过程/后态、身份连续；特写看字形/换行、材质、厚度、光影、正反面与透视 |
| 相机 | 取景目的明确，抵达后可读，离开和下一主体接手连续；幅度由内容决定 |
| 边界 | 资产与实例完整画幅、没有中间固定clip；最长文字、最大缩放/旋转/交叠和相邻帧无意外截字/空场 |
| 组合 | 保留人物窗与口型时钟，避开字幕/证据/操作；背景弱视差与前景实际相机一致，点阵不透过非焦点纸面 |
| 字幕与声音 | 原生字幕有字级和语义重点，音乐积极且不抢口播；实际混音情绪与技术指标分开验收 |
| 同源对照 | 横竖样段同版本、同内容与同套组件；与参考并列看材质/运动，分别检查手机阅读和整体轮廓 |
| 运行与交接 | 属性更改/恢复实际生效，默认值与覆盖合并核对，随机寻帧可复现，当前源/实例/实际导出/证据同版 |

连续观看、实际听审、用户审美/节奏认可和观众理解分别记录；结构校验、解码或抽帧不代替这些结论。未通过时修对应对象、取景或结构，不用缩小所有内容、加遮挡带或换背景掩盖问题。记录到[交接清单](../templates/animation-handoff.json)。
