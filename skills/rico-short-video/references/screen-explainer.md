# 拍屏讲解与混合模式的屏幕段

适用于手机拍摄屏幕、录屏配本人解说及混合视频中的演示段。先按[source-modes.md](source-modes.md)判定素材；ChatCut维护真实画面、主剪、字幕、声音和最终导出，MotionGit按语义提供重点图形。首个手机拍屏演示案例已由用户认可、亲自发布并宣布完成，实测范围见[首条拍屏案例](data/first-screen-case.json)。可复用其制作路径，不把稳像、去频闪、自动跟踪或双源同步写成已验证。

## 入口与素材角色

- 已有原片直接分析、转写和剪辑，不倒补逐字稿审批；未拍时先给简短演示提纲，默认围绕一个可见结果，尽量两分钟内。只补问影响下一步的缺口。
- 记录capture_method：phone_screen、screen_recording或dual_source，以及各源角色、方向/帧率/色彩、主原声、可用区间。设备、桌面或音箱的实拍开场仍可属于同一拍屏演示，不因没有满屏软件界面而改判混合模式。
- 纯手机素材可直接开工。同步电脑录屏是提高文字清晰度的可选输入，不要求用户整条重拍；不可读时只指出缺少的具体页面或区间。录制前可建议放大关键字、正对屏幕并稳定支撑、试录检查反光/条纹；具体设备参数另核实，不承诺自动修复。
- 素材导入沿用当前使用者已经给出的具体授权，不继承维护者历史授权；新增收费、其他目的地、账号权限和最终提交按其具体授权处理，不把制作授权解释成修改系统审批设置。

## 先整理讲述与操作，再剪声音

查看开头、代表性中段、结尾和关键操作帧，结合原声区分用途、真实操作、结果与后续设想。转写只帮助定位，软件名、否定词、状态和设备播报以原声与画面核对。用户口头描述的“配网失败”等片段标签不一定与ASR逐字相同，应根据上下文找到完整无关播报及周围空等，不能只按关键词命中删音频。

在已有主分镜或[动画交接清单](../templates/animation-handoff.json)中按需要记录：原片区间→主时间轴帧区间、当前口播、点击/指向、可见反馈、等待、结果、必须保留的说明及保护区域。引用同一份源映射，不另造多套时码，也不要求用户填写表单。

剪辑分别检查三件事：说话是否顺、动作是否对得上、结果是否看得到。“现在点击这里”应对应实际点击；删静音不能把点击和反馈剪没，也不能把不同状态拼成同一次实测。保留“后面打算”等限定，团队共用等设想不能变成已部署结论。

无口播长等待可压缩、加速或节选，并按真实改动说明；短等待若能建立操作→反馈的因果，可保留。说话默认原速，不为凑时长整段倍速。每次删段/变速后更新字幕、放大、动画和音效的成片时钟；主剪稳定后再批量制作动画。

## 先保护真实主展示，再安排动画

当前操作位置、完整状态/结果、指针或手势、必要上下文和原生字幕组成保护区。保护区随镜头和手持移动更新；信息密集或需要读原界面的区间可少放或不放动画。不靠缩小整页、加遮罩或生成界面来腾出动画位置。

| 当前表达 | 优先处理 |
| --- | --- |
| 展示可见结果、真实设备播报 | 直接用实拍建立开场，标题放留白；不强加露脸、头像窗或纯动画片头 |
| 当前重点/解释 | 短关键词、编号、线条或轻提示直接叠在真实视频上 |
| 多种状态、多个步骤 | 按当前语句逐项出现，复用模块的局部区间；不一次铺满整个长列表 |
| 点击、连接反馈、结果阅读 | 实际画面与准确局部放大优先，按需要暂时让出动画 |
| 总结 | 短结论或小流程收束，仍保留真实场景 |

动画密度按语义分布：开场、转折、状态、步骤和总结都可出现有用变化，不以“只放过一次动画”算完成，也不固定每隔几秒必须出现。本条5个模块落成13个独立实例是案例，不是以后每条的最低数量。默认无大面积纯色底；只有确实改善对比时才用最小局部底板。整体文字层级、颜色、线条和运动语言保持一致。

## 透明交接与局部返工

当前已实跑的路线是MotionGit普通渲染→仅图形素材去底/细描边→VP9 alpha WebM→ChatCut独立图层→编辑器组合与云端H.264实际像素。主视频、原声、字幕和混音继续在ChatCut，不在本地将整条视频压平。模板原生alpha或新格式另行验证，不能从本条去底成功推导。

先读实际图形配色再去底。本条浅底亮字关键词曾连字一起被去掉，改暗底亮字后去暗底、加细深描边；浅底黑字列表/流程则去亮底、加细浅描边。保留文字、数字、发光边与细线，不能把同一阈值用于所有模块，容器alpha标记也不能代替像素检查。详细交接见[hybrid-workflow.md](hybrid-workflow.md)。

新模板、配色或交接方式先取能暴露问题的短样：实际文字、真实屏幕背景、进入/停留/退出及一次操作反馈；合成后检查透明边缘、中文完整性和遮挡，再批量复用。已验证的同类方案按改动范围检查，不每条重装运行环境、重下模板或增加用户确认节点。

模块内部改字回MotionGit源参数重渲染；位置、裁切、时长和声音归主工程。保存普通渲染、透明文件及源参数。修改几何前读实际源尺寸和实例：本次ChatCut width/height表示完整未裁切媒体，crop另计，直接把可见裁切框写成整帧宽高会出错。由目标区域反推整帧大小与位置，按当前工具合同落位。

## 屏幕文字与移动镜头

放大必须对应当时说的按钮、完整句子、状态或结果，保留必要名称、单位与上下文。按当前源帧的真实像素框处理，考虑裁切、透视与父层变换；手持镜头移动后重新定位，不沿用固定点位导致框偏离。长句优先矩形局部，圆形镜片只用于能完整容纳的短目标。

手机观看尺寸下检查的是观众需要读懂的当前目标，不要求整页所有小字都读清。裁切、透视/水平校正、稳像、去频闪和自动跟踪各自试验，未实测就记录未验证；放大无法补回丢失的信息。补截图/录屏先核对同一页面、状态和结果，标明补录或重演，不用生成文字冒充原始界面。

## 声音、字幕与双源

现场有信息的音箱/系统播报属于演示证据，不默认当噪声删除。主讲解与设备播报来自同一原片时保留一条原声路径；MotionGit对齐用旁白和重复视频音轨静音。设备播报或关键解释时优先清楚听见原声，按需要延后/压低配乐；音效服务关键进入和状态切换，不每个字都加，不盖住播报关键词。本条首段播报不铺配乐，后续配乐由ChatCut统一ducking，是按素材选择的做法，具体增益与阈值不固化。

字幕由ChatCut统一维护，校正Codex等术语，避开当前操作目标；不叠模板字幕。最终检查和归档读取当前原生字幕卡、程序参数和词级时码，不能拿旧ASR段落数/SRT代替当前显示版本。

双源时按实际共有的页面切换、点击反馈或声音对齐，核对两份帧率与开头、中段、结尾及切点；不能凭创建时间或同时从0秒播放宣称同步。通常保留手机主声，辅助录屏静音；实际质量不同再据实选择。仅有手机素材时不倒填双源同步通过。

## 验收、封面与下一条

约360—390像素宽检查当前目标、字幕、动画和设备主体的主次；进入、移动、停留、退出都要抽查，最终MP4再检查实际像素。核对操作链、事实限定、唯一主原声、设备播报与音效。解码、抽帧、连续观看、完整试听与用户认可分别记录；首条完成不补填助手未做的全片观看/试听。

纯拍屏封面可以有本人，按用户许可复用真实肖像，保持身份与眼镜；也不因此要求每张必须有人。按production.md默认交付16:9、3:4、4:3，各自构图，先读上一条已认可封面，保持系列一致；真实设备/界面素材可作视觉线索，不套用视频讲解卡的小字阅读标准。

发布与完成后归档按publishing.md、archiving.md接续。原生时间轴、实例、字幕、源映射、实际媒体与动画参数是复剪依据，XML限制和仅云端音效等依赖明确注明。新一条复用本页流程与案例；新的修复能力、双源及混合模式仍按各自素材验证。
