# ChatCut与MotionGit的制作分工

这是基于首条视频实跑、用户反馈和本轮优化请求形成的默认制作方法。ChatCut维护最终主工程，MotionGit按需提供重点动画。用户明确指定工具或交付形式时优先遵从。本项目已实测纸面透视竖版2.5.7的H.264 MP4局部资料卡；后续纯拍屏V2已实跑MotionGit普通渲染去底、VP9 alpha WebM导入ChatCut及云端H.264短样和完整成片，见本页交接方法。模板原生alpha输出、原生.motion工程互通和提速比例仍未验证。

先按[source-modes.md](source-modes.md)决定露脸、拍屏或混合模式与任务入口。已有原片可直接分析；拍屏段先读[screen-explainer.md](screen-explainer.md)，同时保护操作因果与原声，而非只按逐字稿排镜。人物要求只在适用素材区间执行，主时间轴、Rico署名、真实内容、声音和发布/归档规则共用。

## 按观众要理解的内容分工

| 工作 | 默认负责方 | 判断依据 |
| --- | --- | --- |
| 剪停顿、重复、接句，整理原声和实际时间码 | ChatCut | 保留可编辑的口播主线，修改后核对关联图层 |
| 按内容调度真人的全画幅、分区、人物窗、位置与大小变化 | ChatCut主工程 | 按presenter-layout.md选择，人物与原声共用主时钟，新窗形/抠像先验证，检查口型和遮挡 |
| 关键词、轻量图解、真实截图高亮与局部放大 | ChatCut | 精确对应源图位置，并方便修改 |
| 方法步骤、对比关系、信息层次、有辨识度的视觉转场 | MotionGit候选 | 合适且已验证的模板编排有明显收益，实际字号、真实素材及交接方式满足本条要求时使用 |
| 总字幕、配乐、音效平衡、平台片尾、最终导出 | ChatCut | 各项只有一处最终维护位置，统一审看与改稿 |

ChatCut也能制作动画，MotionGit模板也可能覆盖完整口播。以上是本项目的编辑选择，不是功能排他划分。每段只选一个动画制作方；简单内容可直接在ChatCut完成，不设MotionGit使用比例。需要使用MotionGit但模板不适配时，说明具体限制与可审核替代，不冒充已使用该工具。

MotionGit候选的发现、筛选、比较和复用按[motiongit-selection.md](motiongit-selection.md)。先确定本期要表达的关系和素材，不从喜欢的模板反向改写口播；一个主视觉方向内按镜头选择合适组件。

## 制作顺序与共同时间基准

1. 先明确观众应记住什么、能马上做什么及真实会员承接。按入口选择前置稿件、演示提纲或实际原片分析；已有原片不倒补写稿审批。
2. 在ChatCut完成主讲解精剪，拍屏段先核对原声与操作事件、无口播等待和结果，双源核对同步；再检查接句和事实限定，记录可制作的口播版本与源区间映射。转写用于定位，口语节奏和完整试听分别验收。动画从这个版本出发。
3. 按实际语音重排分镜。每个镜头记录“口播锚点、表达目的、真实素材、适用的人物布局或屏幕操作目标、动画负责方、音效锚点”；屏幕镜头另记操作顺序、变速与源到主时间轴映射。人物的起止位置、大小、窗形和过渡按presenter-layout.md选择；一个时刻突出一个主要信息，阅读量决定停留时间。
4. ChatCut先放好实际存在的真人或屏幕主展示、资料和字幕安全区，再把画面区域、实际时长及素材交给MotionGit。人物有移动时同时提供移动过程的保护区域，不能只按终点留位。MotionGit不能反向改写主口播或占满人物位置。
5. 新风格、原片类型或交接能力先选代表性段落核验；拍屏首条通常20—30秒，包含真实文字、一次操作反馈、镜头移动和声音，有人物才检查人物。已确认同类制作复用，不重复增加确认节点。首条最终交付已推进至V4并由用户宣布任务完成，不再从旧17秒试验起步。
6. 在ChatCut合入已核对的动画，完成细节、声音和平台片尾，再检查实际导出。保留主工程、MotionGit实例及对应版本。

四平台共用同一口播主段与素材，需要不同承接时再派生片尾和输出，记录对应时间轴/版本；中性结尾可共用同一主片，各平台文案分别准备。主段有修改时标记派生版本复核，避免四份独立主剪各自漂移。

项目帧数为最终时间依据，场景区间统一为左闭右开`[start_frame, end_frame_exclusive)`。动画内部使用相对时间；项目fps、素材fps和动画运行fps分别读取，不能一律假设60或30。画幅和帧率依据原片与输出要求选择；30fps原片不会因复制成60fps变得更清晰。调整已制作版本的参数须作为明确变更处理。

实际使用跨工具素材时，由助手填写[动画交接清单模板](../templates/animation-handoff.json)，保存到本条剪辑工程目录，用户无需填参数。同一镜头在既有分镜中引用交接ID，不再手工维护第二套时码。模板空值和not_checked不是可交付结果；人物等专用检查在不适用模式/区间写not_applicable并给原因，不伪造通过。

## MotionGit怎样交给ChatCut

`.motion`保留在MotionGit实例侧。不能假设它可作为ChatCut原生工程导入，也不能承诺渲染后的视频能在ChatCut逐字、逐图层编辑。需要改动画内部内容时，回到其源实例，渲染该模块的新版本，再在主工程中替换并核对。

按实际能力选择交接方式：

1. **经验证的透明动画。** 原生alpha输出与普通渲染后制作透明素材分开记录。2026年10月17日已实跑“MotionGit普通MP4 → 仅动画图形去底及细描边 → VP9 alpha WebM → ChatCut浏览器组合与云端H.264短样”，拍屏可按相同编码与工具路线复用，仍检查本条文字、边缘、时钟与实际导出。亮底黑字与暗底亮字分别处理，避免去掉浅色文字、编号或发光边；不能把原片在本地压成最终组合。保留普通渲染和透明派生文件，原声、字幕、位置与混音仍在ChatCut维护。这不证明模板原生alpha输出、所有MOV/WebM编码或其他导出路线均可用。
2. **局部动画资料卡。** 无alpha时，使用实际渲染的普通视频作为独立资料卡，保留比例和必要来源；适用露脸区间的人物窗保持清晰。拍屏模式按用户新要求优先采用真实视频上的透明内容叠层，不能因普通MP4容易导入就默认铺大面积纯色卡；没有已验证的透明或去底方案时先核对工具能力，仍保护操作目标和真实反馈。H.264 MP4作为兼容基线，首个实际MotionGit片段仍须检查导入与输出；纯色整帧MP4不能当透明层覆盖真人。
3. **ChatCut原生实现。** 简单图解、精确界面操作，或模板难以适配人物与可读性时，在ChatCut按已确认风格实现，真实素材独立绑定。记录实际制作方；“参考MotionGit风格”不是“MotionGit渲染”。不假定不同引擎代码可直接复制运行。

MotionGit支持独立选段时按模块出片。若当前模板要求完整旁白归属或整片计划，满足真实合同后可从已验证的完整渲染取用对应片段；不能删必要旁白、伪造归属或跳过检查来强行切小段。普通字幕、名牌能关闭时在模板侧关闭，统一在ChatCut添加；否则在保留目标内容和必要标识的前提下选取信息区域，仍无法避免冲突时换实现方式。

新版本素材以新资产导入，保存旧版本，在原场景位置替换并核对区间、尺寸与效果。官方“缺失素材重新链接”用于恢复同一源文件，不能用它悄悄换成不同剪辑。

### 声音归属

- ChatCut保留一份主口播，人物重复实例静音。传给MotionGit的同段旁白可用于动作对齐，回收动画默认不带入其旁白。
- 动作音效尽量独立交接并标注锚点；模板没有可用独立音效时，静音其混合音轨，在ChatCut按动作配适当音效，不把整段混音叠到主口播上。
- 配乐由主工程统一管理，沿用已选或已授权曲目。分段动画不各自带一首音乐。依照实际听感检查旁白、音乐和动作音效的主次。

## 真人、信息与风格

先按source-modes.md区分人物和屏幕镜头。纯拍屏突出实际操作、结果和本人原声，动画不盖关键按钮/文字；手持移动时重新定位提示，画面修复和自动跟踪能力须实测。露脸及混合的可用人物区间编排按[presenter-layout.md](presenter-layout.md)：依据此刻观众主要看人物、资料还是关系来选构图；全画幅、适度近景、上下/左右分区、圆角或圆形人物窗按内容使用。段落主次变化时调整，复杂资料阅读时保持稳定，不用固定角落或轮换顺序覆盖整片。新形态仍须实际验证，已验证的小样不等于所有形式都可用。

露脸口播先保留2—3秒全画幅真人，默认前3秒。人物窗应能辨认表情与口型，不只是证明“有个人”。缩窗和原本纯色的整帧画面使用同源动态视频铺底，再叠纯色半透明罩；背景保留环境和运动，前景人物清晰，按[presenter-layout.md](presenter-layout.md)控制主次。MotionGit资料卡位于该背景上方，不再用整帧不透明底盖掉视频。动画密度体现为持续有助理解的变化，不是所有元素同时运动。长截图只把相关部分放到可读尺寸，数字、事实限定及“教学示例/数据虚构”保持完整。

共同视觉规范包括字体、层级、颜色、边距、人物边框/阴影语言、图解线条、动效节奏、字幕和封面关系；人物位置、大小和窗形随镜头任务变化。先读当前官方工具对风格选择和字体的要求；按用户认可的具体反馈选择共同规范。Rico作者名、真实素材及会员权益沿用已确认要求；首条完成可作为参考，但绿色、纸面、窗口大小和音效强度不能自动变成所有视频的系列标准。

复用已认可的姓名条、关键词、证据放大、步骤/对比、会员引导等组件。相同表达任务与结构可换参数复用；不同任务用合适版式，避免整条视频都套一个卡片。素材和风格实例留在项目，技能只保存方法与入口。

## 改稿与验收

| 改动 | 更新范围 |
| --- | --- |
| 口播剪辑、句序或实际时长变化 | 更新主时间码及受影响的字幕、动画、音效和片尾，复核相邻镜头 |
| 替换截图或录屏 | 更新源尺寸、目标矩形和实际显示映射，重新检查原图与局部 |
| 改字或人物窗位置 | 修改对应图层，检查长文案换行及人物/字幕/资料遮挡 |
| 修改MotionGit动画内部内容 | 改源实例，出新素材版本，替换相应镜头；保留原版本和放置依据 |
| 改会员权益或平台引导 | 核对真实内容，更新对应片尾、封面或发布文案 |

验收分四项记录：口播是否连贯且保留原意；画面是否准确且能读；两工具交接是否同步、完整；用户是否认可整体观感。看实际组合帧的进入、移动、停留和退出，再核对最终输出；“工具成功”“有像素变化”或“音频相关性高”不能代替内容验收与完整试听。

完整V2已经使用MotionGit渲染的标题、列表、步骤、对比、会员权益等局部卡片；原图精确放大和人物由ChatCut统一控制。字幕的预览与实际导出曾不一致，按[chatcut.md](chatcut.md)检查成片像素。这是首条露脸任务的历史范围。后续纯拍屏V2已验证现代图文普通渲染去底、VP9 alpha素材及完整ChatCut成片，并由用户认可完成；模板原生alpha、其他模板和整条效率比较仍未验证。证据见[first-screen-case.json](data/first-screen-case.json)，用户审美认可不从技术成功推导。

首条最终V4及用户明确完成确认更新了任务状态；下次复用[制作入口](next-video.md)而非重跑V1。用户明确结束时按[archiving.md](archiving.md)备份当前实际实例及依赖，再删除淘汰版本。
