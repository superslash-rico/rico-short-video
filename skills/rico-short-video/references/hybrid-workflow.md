# ChatCut主工程与原生MG模块

当前MG视觉、参考、全画幅结构与横竖样段基准统一由[共享规范](mg-visual-standard.md)维护。本页不另建视觉标准。

2026-10-22起，主工程继续由ChatCut维护，动画改用当前支持的原生可编辑MG源码；不再把MotionGit选模板、建库、下载或渲染作为新制作步骤。实际创作读[animation-production.md](animation-production.md)、[整体设计与运镜](mg-whole-first-and-camera.md)；源码绑定读[native-mg-runtime.md](native-mg-runtime.md)。历史MotionGit工程只按其锁定版本恢复，本次变更不自动重做已交付视频。

先按[source-modes.md](source-modes.md)决定露脸、拍屏或混合与任务入口。已有原片直接分析；屏幕段按[screen-explainer.md](screen-explainer.md)先保护操作因果、真实反馈和原声。有可用露脸素材的区间按[presenter-layout.md](presenter-layout.md)持续显示实时人物；纯拍屏不强加人物。

## 主工程与动画分工

| 工作 | 维护位置 |
| --- | --- |
| 停顿/重复精剪、接句、主口播与源映射 | ChatCut主工程，修改后复核关联图层 |
| 全画幅、分区、人物窗的形状/位置/大小及所选背景 | ChatCut主工程按presenter-layout.md调度，前景肤色不染色，复制层静音 |
| 原始截图/屏幕视频、准确源像素高亮和局部 | 普通真实媒体独立维护，精确联动机制才内部绑定 |
| 组成/流程/比较/判断等动画解释 | 原生MG源码与属性，独立图层，整体→模块→镜头/对象变化 |
| 原生字幕、配乐、ducking、动作音效与平台片尾 | ChatCut统一维护，主口播和主字幕各一份 |
| 总装、实际编码、色彩验收和最终交付 | ChatCut主工程及原质量检查流程 |

一个镜头有明确的动画源、资产和目标实例，不并行维护两套相同内容。简单任务直接用简单图形；复杂关系用合适解释机制，不设工具或复杂度使用比例。图形内部摄影机不接管人物窗与字幕。

## 制作顺序与统一时钟

含人像原片先按[color-quality.md](color-quality.md)完成source阶段，最终实际编码另过final同帧检查；由助手检查，不增加用户逐段确认节点。

1. 按入口完成必要稿件或实际原片分析，明确观众应记住的观点、能做的动作与真实会员承接。已有原片不倒补写稿审批。
2. 在ChatCut稳定主讲解精剪，拍屏保护操作→反馈→结果，双源核对同步。保存可制作版本和源到主时间轴映射，核对事实限定、接句与转写；转写、口语节奏和实际试听分别记录。
3. 看整条讲述后按理解任务分镜，记录口播/事件锚点、真实素材、人物或操作主展示、MG解释机制、起止区间和音效事件。人物变化仍按presenter-layout.md，重要阅读保持稳定。
4. 先放好人物/屏幕、字幕和真实资料，再将它们的全程区域作为排版约束。MG整体与世界使用完整画布，允许画外空间；通过构图、路径、层级和错时避让，不用保护区生成中间裁切窗口。空间不足时重排或分阶段，保留主要阅读单位。
5. 依据共享规范及当前MG技能编写源、导入、设置属性并放置实例。首次建立统一风格先完成同内容横竖对照样段，再扩展整片；新机制选能暴露问题的代表段，检查真实内容、整体/特写、一次对象变化、人物过渡与声音；沿用已确认风格与授权，同类通过后复用，不重复增加审批或安装步骤。
6. 在实际主工程验进入/中途/读时/交接/退出及手机尺寸可读性，核对存储属性和当前绑定，再完成混音、片尾及实际导出。只修受影响模块与相邻镜头，保留可回滚版本。

四平台共用一份主剪，确需不同承接时才派生片尾/输出，记录对应版本；主段变化后复核派生版本。中性结尾可共用，文案分别准备。

最终项目时码用绝对帧，区间左闭右开`[start, end)`；MG用局部秒数。项目fps、源fps、MG运行fps分别读取，不硬套30/60或从源文件名猜时基。代理/方向/HDR处理、时长和输出标准按原制作规则，不因新动画方法改变。

助手在[动画交接清单](../templates/animation-handoff.json)引用主分镜与源映射，记录源/属性/实例/当前输出的对应。空值、not_checked不是通过；不适用人物或屏幕检查写原因。

## 原生组合与必要烘焙

专业MG采用完整工程画幅的原生图形层，入口、共享组件、参数版本与支持源码保存在本条工程，保持可编辑；真实媒体、人物与字幕独立。专业主展示使用共享深紫黑点阵与横向微光，不用中间固定窗口。普通人物画面和纯拍屏的局部透明提示保留真实原片；全画幅资产不等于必须不透明覆盖所有原片。

仅在当前宿主能力或明确交付需要时烘焙图形模块，不将整条主片在本地压平，也不默认退回MotionGit。先核对当前工具合同、费用/传云授权，再验证实际帧率/时长/声音/透明像素、导入、编辑器组合与最终编码。原生透明合成、透明视频导出和后处理去底是不同路径；容器alpha标签不能替代像素，旧MotionGit→VP9通过不证明新原生烘焙链路通过。

无alpha的模块只能作为适合的局部资料卡，保留比例及必要来源，不能当整帧覆盖层。需要修改内部字图/过程时回原生源/属性，更新目标资产/实例并检查实际结果；仅位置、裁切、时长等问题在主工程改。保存最终有效值和旧版本，缺失媒体重链接只用于恢复同一源，不悄悄换剪辑。

## 声音、视觉与复用边界

ChatCut保留唯一主口播和原生字幕，人物/背景复制实例静音。MG对齐用的参考音频不进入成片，图形模块不重复旁白或总字幕。动作音效独立维护并记录有效瞬态；配乐继续沿用原已选/已授权曲目，由主工程统一ducking，分段不各带一首音乐。

共同字体、颜色、层级、边距、边框/阴影、运动及字幕/封面关系沿用本条已确认规范；位置、大小、窗形按内容变化。真实资料按手机可读的局部与完整条件呈现。新窗形、抠像、透明导出等能力按实际证据验证，不由方法文字或旧工程结论推断通过。

已认可组件可按相同表达结构复用；不同理解任务重新设计，不让整条套一个卡片。原生源码方法的新完整样片仍待实际制作验证，技术、连续视听和用户审美认可分开记录。
