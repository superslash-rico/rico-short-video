# 短视频原生MG创作

专业MG首先执行[共享视觉与质量规范](mg-visual-standard.md)：以同源参考、材质/空间组件、全画幅场景与横竖对照样段保持长短片质量一致；本页保留内容创作顺序。

用于已明确需要动画包装的口播、拍屏或混合短视频。2026-10-22起，动画创作采用当前ChatCut支持的可编辑Remotion/HTML源码，取代MotionGit模板生产。主剪辑、原声、字幕、人物窗口、色彩、混音、封面和发布仍走本技能原路径。方法依据与验证边界见[来源说明](mg-method-source.md)。

## 先决定动画解释什么

先理解整条已剪讲述、实际画面和上下文，再分配语义单元。每单元写清：观众应理解什么、依据是什么、哪些对象/条件必须保留、哪个对象如何从前态变为后态。动画解释组成、对比、处理、判断、纠错或因果，不能仅给每句话配一个会进出的标题。

优先用同一对象的分组、移动、拆解/归位、顺序与状态变化表达关系。默认不画逻辑连线；必要连线再检查端点、方向、投影、遮挡与退出。金句/关键词是强调手段，不能挤掉核心论点需要的解释过程。简单问题可用简单动画，不以复杂运镜、模块数量或真实素材比例评分。

真实资料在有证明或解释收益时使用：原件定位 → 当前局部 → 解释/对比 → 回到上下文。保留名称、单位、时间、否定词和条件；分清原始截图、重排摘录、辅助示意与模拟示例。需要补资料时采集可追溯原始来源；用户素材不是开工门槛。不得绘制假UI/报告/输出冒充实际证据。

## 软件图标随提及主动获取

口播明确提到具体软件或应用时，助手自行上网找到真实软件图标并融入相应动效；先核对产品、厂商与所讲端，不用母公司Logo、同名产品或自绘通用符号代替。

- 优先软件官网、官方品牌/媒体资源或官方仓库。实际查看图片后再选用；官方图中已有清晰图标时可以作对象内部取景，保留原图。确需第三方来源时核对身份、来源和适用使用说明，不将其标为官方。保留原配色、比例和必要留白，避免低清favicon、拉伸或凭空重绘品牌图形。
- 文件存入本条工程/素材目录，记录来源页、原图URL、取得时间、摘要、尺寸与实际裁切/用途。下载文件和实际媒体依赖随工程留存，不把每个品牌图标或有时效的URL硬编码到技能。不能仅依赖远程链接在渲染时加载。
- 对齐软件名的真实口播/字幕词时码，在首次识别或再次承担动作角色时编排入场、交接、指向或归位；图标参与当前解释，不机械贴在每句话旁。可独立放媒体层；需要随场景透视/局部取景时，按当前宿主合同绑定真实项目图片ID并暴露图片属性。实际合成和编码后检查显示、透明边缘、完整图形、人物/字幕避让、最大运动、手机尺寸及参数更改/恢复；不把导入成功当作动效已显示。

## 创作顺序

1. **读取主工程约束。** 使用当前粗剪版本、真实口播锚点、源到主时间轴映射、实际画幅/fps。按[source-modes.md](source-modes.md)判断模式；含人像源先过[color-quality.md](color-quality.md)的source阶段。人物/字幕/关键操作区域先落位，记录过渡全程保护区。
2. **参考与整体先行。** 按共享规范实际观看参考、研究可用组件，并记录认可范围；先完成同一内容的横竖对照样段基准。 按[整体设计与运镜](mg-whole-first-and-camera.md)完成开场整体、必要中间重组和结果整体，确定主次、分组、比例、留白及视觉重心。整体是一个可理解的单位，不是整条视频塞进一张图。
3. **再做模块细节与状态。** 每个需要特写的对象有真实内容、完整读序和可见的前态/过程/后态；全景与特写共享对象身份。字形、边缘、层次、厚度、光影及透视按用途统一，不用假细字和空白占位冒充精致。
4. **分别编排镜头与对象。** 镜头决定观众观察哪里，对象运动解释发生什么。先排口播锚点、抵达与阅读、退出和交接，再配合有意义的音效。竖屏节奏可以紧凑，仍须足够读时；不采用长课固定帧数或固定缩放比例。
5. **写原生源码。** 读取当前环境对应的create-motion-graphics技能，沿用已确认风格，并依其要求查阅具体参考和运行时文档；原生参考浏览不等于恢复MotionGit模板生产。按[native-mg-runtime.md](native-mg-runtime.md)保存项目内入口、支持模块、属性定义、默认值和实例覆盖。普通真实视频、图片、人声与字幕继续独立维护。
6. **放入主工程验证。** 按[hybrid-workflow.md](hybrid-workflow.md)以独立图层组合，先检查代表段，再按复用条件展开。用[动画交接清单](../templates/animation-handoff.json)引用同一主分镜，助手填写，不要求用户填表或逐镜头重新批准。

## 与短视频人物/拍屏规则衔接

人物全部按[presenter-layout.md](presenter-layout.md)：适用露脸段持续保留实时人物，默认前3秒全画幅真人；随后位置、大小、窗形随内容变化，阅读段保持稳定。普通人物组合可用同一时点源视频加轻色罩；专业MG主展示用共享深紫黑背景。清晰人物层不染色，只留一份主原声。纯拍屏不补人物，屏幕段按[screen-explainer.md](screen-explainer.md)保护真实操作与结果。

专业场景的资产/根容器/实例覆盖整个输出画幅，世界可向画面外延伸，相机决定取景。人物、字幕与关键操作是动态排版保护区，不是中间裁切窗口；通过构图、运动路线、层级和错时避让。人物仍由主工程按原规则调度，不把人像缩成标识；背景与MG视觉工艺按共享规范，不移植长片圆窗或字幕流程。

## 声音与交付

主口播、原生字幕、配乐及ducking仍由ChatCut统一维护。原生字幕按[字幕设计](caption-design.md)提高字级与语义重点，不重复嵌入一套MG字幕；配乐按[积极配乐标准](audio-style.md)选择和实听。音效落在提取、落座、拆分、纠错、翻开、合并或转场等实际事件上，标记音频内的有效瞬态和主工程锚点；阅读时留安静，不机械给每个字/每张卡/每次运镜加声。金句可只保留入场强调，不加无意义退场叮声。音效试听与混音按原流程，不把长课的无BGM规则迁入短视频。

保存同版“主时轴 → 源码和属性 → 资产/实例 → 实际预览/导出 → 检查范围”对应关系。源码可编辑不等于已绑定生效；检查当前实例的有效参数和实际像素。最终导出、人物final色彩验收、封面/文案、用户审核及发布授权均按原流程。

横竖样段与成片的认可范围以相应项目真实审核记录为准；没有同版本、同机制认可基准时先建立样段。被用户指出风格和固定裁切问题的旧版不作为达标样片。实际制作验证代表段的原生绑定、确定性、组合和编码输出；技术检查、连续观看、完整试听、用户认可与观众理解分别记录，不能用规范已写好代替实跑。
